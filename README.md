# 과제 14: 힙 정렬, 퀵 정렬, 병합 정렬 성능 비교

## 1. 프로그램

- 데이터: `rand() % 100000` 무작위 정수 (중복 가능), `srand(12345)`로 시드 고정
- 원본 `orig`를 만들고, 정렬 전에 `copyArr()`로 `arr`에 복사했습니다. 모든 알고리즘이 같은 데이터를 정렬합니다.
- 정렬 후 `isSorted()`로 확인했습니다. 오류는 없었습니다.
- 힙 정렬은 `arr` 자체를 최대 힙으로 사용하고, `heapify()`를 재귀로 구현했습니다.
- 퀵 정렬은 피벗 3가지(첫 번째, 무작위, 세 값의 중앙값)를 사용했습니다.

## 2. 측정 방법

- **비교 횟수**: 데이터 값끼리 비교할 때만 `comp++` 했습니다. 반복문 인덱스 검사는 제외했습니다. 퀵 정렬은 중앙값 피벗 선택의 비교도 포함했습니다.
- **실행시간**: 정렬 함수 호출 전후의 시간 차이(ms)입니다. 복사, 확인, 출력 시간은 제외했습니다. Windows의 `clock()`은 1ms 단위라서 `QueryPerformanceCounter`를 사용했습니다. 시간은 한 번 실행한 값이라 조금씩 달라집니다. 그래서 값보다 순서를 보고 분석했습니다.
- **메모리**: 직접 계산했습니다. 원본 배열은 제외했습니다. 함수 한 번 호출의 크기는 (매개변수 + 지역변수의 int 개수) × 4B입니다. 재귀 깊이(`depth`)를 세어서 최대값을 `max_mem`에 저장했습니다.

| 정렬 | 계산식 |
|---|---|
| 힙 정렬 | `12 + depth × 28` (`heapSort` 12B + `heapify` 28B × 깊이) |
| 병합 정렬 | `n × 4 + depth × 20 + 24` (임시 배열 + `mergeSort` 20B × 깊이 + `merge` 24B) |
| 퀵 정렬 | `depth × 20 + 32 + 28` (`quickSort` 20B × 깊이 + `partition` 32B + `getPivot` 28B) |

## 4. 분석

**비교 횟수.** 데이터가 20배 커지면 비교 횟수는 약 30배 늘었습니다 (힙 30.2배, 병합 30.0배, 퀵 29.4배). n log n의 증가(약 28.7배)와 비슷합니다. 세 정렬 모두 n log n에 비례합니다. 병합 정렬이 가장 적습니다. 합칠 때 비교가 한 번이면 되기 때문입니다. 힙 정렬이 가장 많고 병합의 약 2배입니다. `heapify()`가 한 단계마다 비교를 2번 하기 때문입니다. 퀵 정렬은 중간입니다.

**실행시간.** 모든 크기에서 힙 정렬이 가장 느렸습니다 (n = 20,000에서 2.709ms). 퀵 정렬(첫 번째, 중앙값)이 가장 빨랐습니다 (약 1.5ms). 병합 정렬은 중간입니다 (1.895ms). 병합 정렬은 비교가 가장 적지만 임시 배열에 복사하는 시간이 있어서 퀵 정렬보다 느립니다. 퀵 정렬은 배열 안에서 순서대로 읽고 교환만 해서 빠릅니다. 힙 정렬은 비교가 많고 부모와 자식이 멀리 있어서 느립니다.

**메모리.** 병합 정렬은 임시 배열 때문에 n에 비례해서 커집니다 (4,244B → 80,344B). 힙 정렬은 292B → 432B, 퀵 정렬은 400~500B → 560~760B로 조금만 늘었습니다. 둘 다 재귀 스택(깊이 log n)만 사용하기 때문입니다. 퀵 정렬은 병합 정렬의 약 1/100입니다.

**퀵 정렬의 피벗 (n = 20,000).**

| 피벗 | 비교 횟수 | 시간(ms) | 메모리(B) |
|---|---|---|---|
| 첫 번째 | 323,056 | 1.517 | 700 |
| 무작위 | 339,287 | 1.937 | 760 |
| 중앙값 | 320,841 | 1.572 | 560 |

중앙값 피벗은 모든 크기에서 비교 횟수가 가장 적고 메모리도 작았습니다. 분할이 고르게 되기 때문입니다. 무작위 피벗은 결과가 일정하지 않았고, `rand()` 호출 때문에 시간이 약 20~35% 더 걸렸습니다. 이번 데이터는 무작위라서 첫 번째 피벗도 괜찮았습니다. 이미 정렬된 데이터에서는 O(n²)이 됩니다 (이론, 측정하지 않음).

**복잡도.**

| 정렬 | 최선 / 평균 | 최악 | 공간 |
|---|---|---|---|
| 힙 정렬 | O(n log n) | O(n log n) | O(log n) (재귀), 반복문이면 O(1) |
| 병합 정렬 | O(n log n) | O(n log n) | O(n) |
| 퀵 정렬 | O(n log n) | O(n²) | 평균 O(log n) |

실험 결과는 이론과 같았습니다.

**결론.** 비교 횟수는 병합 < 퀵 < 힙, 시간은 퀵 < 병합 < 힙, 메모리는 힙 ≈ 퀵 << 병합 순서입니다. 비교 횟수가 적다고 항상 빠른 것은 아닙니다.
